# 测试说明

线上地址：https://nl-stock-picker.vercel.app  
仓库：https://github.com/aynA-031/nl-stock-picker  
数据优先：扶摇 REST（`FUYAO_API_KEY`）；澄清可选 LLM（`OPENAI_API_KEY`）。

## 1. 主链路（线上 + 扶摇真实数据）

1. 打开 https://nl-stock-picker.vercel.app 。
2. 意图保持「经营改善、估值合理、走势稳定」。
3. 点击「1. 澄清意图并生成条件草稿」。
4. 期望：出现澄清说明与 3 个条件卡（营收同比 / PE(TTM) / 近20日波动率）。
5. 点击「2. 执行筛选」。
6. 期望：
   - 数据模式为 **扶摇真实数据**（不是演示数据）。
   - 列表按入选 / 待确认 / 排除展示。
   - 每只股票含实际值、阈值、来源（扶摇 REST API）、时点、判定理由。
7. 已验证样例（贵州茅台 `600519.SH`，线上/本地扶摇）：
   - 原始字段 `pe_ttm` ≈ `22.605792`（倍）
   - 数据时间取估值快照 `data.timestamp`（约 2026-11-20）
   - 营收同比字段实为 `calculate_operating_income_yoy_growth_ratio`（见 AI 使用记录）
   - 近20日波动率由历史 K 线收盘价推算

## 2. 条件修改与名单进出

1. 默认营收同比阈值约为 `> 0`，完成一次筛选（通常有少量入选）。
2. 将营收同比阈值改为 `10`。
3. 页面应提示「条件已修改，尚未重新筛选」。
4. 再次点击「执行筛选」。
5. 期望：出现「条件变化影响」，列出新进 / 退出名单（例如收紧后比亚迪、中国平安退出）。

## 3. 数据缺失 / 待确认

1. **演示模式**（未配扶摇 Key）：结果中有 `DEMO.MISS`，营收同比缺失 → 状态「待确认」，不得入选。
2. **真实模式**：某指标接口字段缺失时，该条件 `passed=null`，股票为「待确认」并写明原因，不静默通过。

## 4. 冲突边界

1. 将 PE 区间改为下限 40、上限 10 → 「冲突错误：PE 下限大于上限」。
2. 关闭全部条件启用开关 → 「未启用任何条件」错误级冲突。

## 5. 扶摇 / 接口异常

1. 未配置 `FUYAO_API_KEY`：数据模式「演示数据」，红字提示未配置 Key。
2. Key 无效或接口失败：提示「扶摇调用失败：…已回退演示数据」，不伪造成功空结果。
3. Vercel：Key 配在 **Settings → Environment Variables**，修改后必须 **Redeploy**。

## 6. 澄清 LLM（usedLlm）

1. 未配置 `OPENAI_API_KEY`：`/api/clarify` 返回 `usedLlm=false`，使用本地规则启发式（**预期行为**，筛选仍走确定性引擎 + 扶摇数据）。
2. 配置 `OPENAI_API_KEY`（可选 `OPENAI_BASE_URL` / `OPENAI_MODEL`）并 Redeploy 后：期望 `usedLlm=true`（若模型调用失败会回退启发式并仍为 false）。

## 7. 保存策略

1. 筛选后填写策略名 → 「保存当前策略」。
2. 刷新页面后可「加载」回条件；策略存本机 localStorage，不含买卖建议。

## 8. 合规边界

1. 页脚与结果区含免责声明。
2. 无买入/卖出/目标价/必涨等文案或操作。
